# Getting Started with Free-Threaded Python Using NumPy



## Description (500 chars)


This talk will get you started with multi-threaded data processing in free-threaded Python. You will learn how to install the right Python binary, understand the requirements of using free-threaded-compatible wheels, and see concise examples of multi-threaded processing using `ThreadPoolExecutor`. Working with 2D NumPy arrays, we will see what kinds of processing tasks benefit the most from free-threaded execution and how, in some cases, we can process row data twice as fast (or better).


## What will attendess learn

How to install or build a free-threaded Python 3.14t binary, and the importance of using free-threaded-compatible wheels.

How to use `ThreadPoolExecutor` to apply functions across rows of 2D NumPy arrays, collecting results into 1D arrays, 2D arrays, or arbitrary Python objects.

Why immutable arrays (via `flags.writeable`) are a powerful tool for safe multi-threaded processing, and how in-place mutation invites data races.

Understanding which kinds workloads benefit most from free-threading and how multi-threading might still degrade performance.

How to write multi-threaded code that performs well in both free-threaded and GIL-enabled Python.

The current state of free-threaded Python adoption and what to consider before adopting it in your own projects.




For decades, Python has had few good options for running "embarrassingly parallel" operations in parallel. For example, given a 2D NumPy array, parallel processing of row data is an obvious opportunity. In the past, this meant either spawning multiple processes with substantial overhead, or spawning threads that, with GIL contention, might actually degrade performance. NumPy is fast, but with free-threaded Python (3.14t) we can now go even faster: function application to NumPy array rows can be done in half the time (or better) using threads that permit true CPU concurrency.

This talk will get you started with multi-threaded data processing in free-threaded Python. You will learn how to install or build the right Python binary, understand the requirements of using free-threaded-compatible wheels (and avoid accidentally re-enabling the GIL), and see concise examples of multi-threaded processing using `ThreadPoolExecutor`. Working with NumPy arrays, we will see what kinds of processing tasks benefit the most from free-threaded execution. Comprehensive performance tests, across various two-dimensional shapes and worker counts, will be presented.

We will also examine how multi-threading can go wrong, including cases where, even in free-threaded Python, performance can be significantly degraded or how, with in-place mutation, data races can lead to unpredictable outcomes.

There is a catch: bridging Python environments is challenging. The same multi-threaded code that delivers speedups with Python 3.14t (GIL disabled) can perform much worse than single-threaded code on Python 3.14 (GIL enabled). Approaches to writing optimal code for both contexts will be discussed, including branching with `sys._is_gil_enabled()` and using `conditional-futures`, a drop-in `ThreadPoolExecutor` replacement that automatically falls back to single-threaded performance when the GIL is enabled.
